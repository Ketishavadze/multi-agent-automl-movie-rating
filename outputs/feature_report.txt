LLM Feature Engineering Plan:
Feature Engineering Strategy:

1. Release Date Features:
- Extract year, month, and day-of-week from release_date. Year can capture trends over time. Month and day-of-week may reveal seasonality patterns in ratings (e.g., summer blockbusters).
- Create a feature for movie age relative to dataset max year, approximating timeliness.

2. Genre Features:
- One-hot encode or multi-label binarize genres (which are often multi-valued). Genre types strongly influence movie reception, so these are informative.

3. Director and Cast Features:
- From crew (usually JSON or dict), extract the director's name and create a feature counting number of well-known directors based on frequency or external popularity scores.
- From cast, extract main actors (e.g. top 3 billed) and create aggregate popularity or experience proxy features (e.g., average prior movie votes if available, or actor presence indicators). Star power and director reputation affect ratings.

4. Financial Features:
- Use budget and revenue directly. Normalize via log transformation to reduce skew.
- Create profit = revenue - budget and profit margin features to capture financial success.
- These proxies may indirectly reflect movie quality or scale.

5. Popularity and Vote Features:
- Include popularity and vote_count as numeric features because they precede vote_average and indicate audience interest but NOT vote_average itself to avoid leakage.
- High vote counts can indicate wider popularity or marketing reach.

6. Language and Production Metadata:
- One-hot encode original_language to reflect market and possibly quality.
- Encode production_countries and production_companies as categorical - either top N frequent categories with others grouped as "other".
- Feature has_homepage as a binary indicator of marketing presence.

7. Runtime and Status:
- Include runtime as numeric feature since movie length might affect ratings.
- Status is categorical (Released, etc.) and can indicate availability, filtering out unreleased.

8. Textual / Keywords / Overview / Tagline:
- Due to high cardinality and missing data, consider either discarding or applying dimensionality reduction (e.g., topic modeling, embeddings) if computational resources allow.
- These are less straightforward but may add semantic information.

Columns to Remove Before Training:
- vote_average (target leakage)
- original_title and title (unique identifiers that don't provide predictive signal)
- overview, tagline (optional depending on modeling approach; likely noisy and sparse)
- keywords (too high cardinality; may introduce noise unless properly encoded)
- crew and cast raw columns (use engineered features instead)

Summary:
Focus on structured, informative features derived from budget/revenue, genre, release timing, cast/director popularity proxies, and language/production metadata. Avoid text-heavy and unique ID columns to reduce noise. Crucially, exclude vote_average to prevent target leakage but keep vote_count and popularity as reflective audience interest metrics. This approach balances domain knowledge and modeling practicality focused on predicting whether a movie is highly rated.
